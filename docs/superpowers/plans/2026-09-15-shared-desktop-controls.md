# Shared desktop and population controls

**Goal:** 用户控制全桌面苍蝇和蟑螂总数；生物保持身份和速度，按实际屏幕位置跨越相接边缘。

**Design:** 一个 SimulationWorld / MouseTracker / CreatureManager，由所有屏幕窗口共同观察。窗口仅负责自己矩形内的绘制和 DPI。DesktopLayout 计算显示器矩形并集和外露边界，内部接缝不构成墙壁。蟑螂正常爬行不能穿过没有屏幕的区域；逃跑可以从外露边缘藏起。苍蝇跟随全桌面鼠标。热插拔保留总数，将失去屏幕的个体放回最近的有效位置。

**Controls:** 中文 WPF 窗口，通过托盘“数量设置”或双击图标打开；启动脚本显示窗口。苍蝇 0–20、蟑螂 0–500，默认总数 1/20，不随屏幕数改变。“保存并应用”校验整数并保存到 %AppData%/DesktopLife/settings.json。保留同种现有个体，仅补充或减少差额。窗口显示按物理坐标缩放的显示器布局、全局暂停/恢复，关闭窗口后程序留在托盘。

**Visual direction:** 小型桌面控制台，浅灰蓝背景 #F3F6FA、白色面板 #FFFFFF、深蓝文字 #17324D、蓝色主操作 #2563B8、次要文字 #596B7D、边框 #D6E0EA。中文 Microsoft YaHei UI，数值与屏幕标签用 Segoe UI；屏幕排列图是主要视觉识别。所有操作使用标准键盘可达控件。

**Tech stack:** 现有 .NET 10 / WPF / Win32，无新外部依赖。

- [x] Geometry: 先写并集、左右/上下/负坐标/错位接缝、空隙和穿越路径的失败测试；实现 DesktopLayout 外露边界与连续移动约束。
- [x] Simulation: 全局群体、数量差额调整、跨屏行为、热插拔保留；替换旧的每屏倍增测试，并验证跨屏身份/连续性、计时只更新一次及空群体。
- [x] Controls and viewports: 窗口使用各自视口绘制共享世界；添加数量窗口、布局图、托盘入口、配置保存与错误提示。
- [x] Verification: 单元测试、双屏 HWND/穿透、真实设置窗口和配置往返、跨屏渲染接缝/不同 DPI、暂停热插拔诊断、独立复查；更新文档，发布启动，提交并推送 GitHub。

用户当前要求取代“每屏固定 1/20”规则。物理屏幕不相接时，蟑螂不瞬移过空隙；可通过 Windows 显示设置使屏幕边缘相接。
