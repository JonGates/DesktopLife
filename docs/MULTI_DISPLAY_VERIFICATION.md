# 多屏支持验证记录

日期：2026-09-15。用户追加要求：支持多屏，数量按屏幕倍数设计。

## 实现

- 每个 Windows 逻辑显示器固定 1 Fly + 20 Cockroaches；2 屏为 2 + 40，3 屏为 3 + 60。
- EnumDisplayMonitors / MONITORINFOEX 取得设备 ID、物理矩形与主屏标志。每屏一个透明窗口和 SimulationWorld。
- DesktopHost 统一订阅显示设置变化与渲染事件，每帧只采样一次鼠标并更新所有世界，避免窗口数造成时间步长倍增。
- 鼠标归属采用左上包含、右下不包含的屏幕矩形；接缝不会同时召唤两屏苍蝇。
- 新接入、移除、位置或尺寸变化时同步世界和窗口。未变化的屏幕保留状态；改变位置/尺寸的屏幕重新生成。重复通知和主屏标志变化不增加数量。
- 全局暂停隐藏全部窗口并取消渲染订阅；暂停期间接入的窗口保持隐藏。恢复重置每屏鼠标基线。
- 每个窗口独立读取 WPF DPI；DPI 更新后重新应用对应显示器的物理矩形。托盘显示屏幕数和总数量。

## 证据

- artifacts/display-probe/native-windows.json：发布版真实双屏 HWND、样式、坐标和 DPI。
- artifacts/display-probe/topology.json：实际显示器清单，以及注入布局的生产 DesktopHost 生命周期结果。第 8 步已释放窗口；Simulation 数量是退出前最后的逻辑快照。
- artifacts/live-multidisplay/samples.json：真实双屏 App 的更新、可见数量和暂停/恢复采样。
- artifacts/live-multidisplay/live-overlay.png：主屏 RenderSurface 透明截图。
- artifacts/render-multidisplay/population-{100,125,150}.png：离屏渲染结果。

## 性能与验证边界

双屏群体出现后及恢复后的 11 个采样点，共享主循环约 26.99–31.62 Hz，平均 29.13 Hz，两屏读数相同；这是更新频率，不是 GPU 帧率。逻辑更新约 0.014–0.016 ms。暂停约 4 秒内 CPU 时间只增加 0.0625 秒，模拟时间不变。

**仍未达到稳定 60 FPS。** 本次没有开展长时间或活跃鼠标压力测试，不能把短期诊断视为性能验收。诊断包含离屏截图，内存值也不等同独立发布进程的常驻内存。

实际硬件覆盖是两屏并排、各 1920×1080、100% 缩放。负坐标、热插拔和布局变化通过可注入的显示器提供器驱动生产管理器和真实 HWND 验证，没有改变操作系统显示设置；物理拔插、混合 125%/150% 系统 DPI 和 DPI 切换消息路径仍需实机验证。
